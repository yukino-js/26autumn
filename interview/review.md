## 高频踩坑清单

| #   | 踩坑                                             | 正确姿势                                                                                                       | 来源           |
| --- | ------------------------------------------------ | -------------------------------------------------------------------------------------------------------------- | -------------- |
| 1   | 把「20 MB 单个 JSON」当成 JSONL 来流式按行解析   | JSONL 每行是独立 JSON 值；单个大 JSON 必须先拆行或换 SAX 式流式 parser                                         | R02            |
| 2   | 高并发大 body 题一上来就谈「换个更快的 parser」  | 先算量级（400 GB / 320 Gbps / TB 级堆），判定为容量题，再分层防守                                              | R02            |
| 3   | JSONL 只追加、不轮转                             | 按大小/时间轮转 + 压缩 + checkpoint（`activity.jsonl` 的 10,000 条上限）                                       | R02 · 项目事实 |
| 4   | 说出「cookie 的 same origin」                    | 没有这个属性；分清 Same-Origin（scheme+host+port）/ Same-Site（eTLD+1）/ Cookie 作用域（Domain+Path）          | R03            |
| 5   | 拿 CORS 或 `HttpOnly` 当 CSRF 防线               | CORS 只控读响应、请求已到服务端；`HttpOnly` 防 XSS 窃取，不防 CSRF                                             | R03 · 项目事实 |
| 6   | 只靠「接口只收 JSON」防伪造                      | 表单可用 `text/plain` 拼出 JSON 字符串；须叠 Token / 自定义头 / `Sec-Fetch-*`                                  | R03 · 项目事实 |
| 7   | 以为 `SameSite=Strict` 万事大吉                  | GET 副作用、同站子域被接管、WebSocket 需服务端单独校验 `Origin`                                                | R03            |
| 8   | 把「一定时间范围」直接当固定窗口                 | 边界可放行 2×limit；严格语义要用滑动窗口日志                                                                   | R04            |
| 9   | 用 `shift()` 裁时间戳、只裁不清 key              | `head` 指针均摊 O(1) + 压缩；`sweep()` 清空闲 key 防 Map 泄漏                                                  | R04            |
| 10  | 进程内计数器直接上多实例                         | 各进程计数独立失效 → Redis zset + Lua 原子（检查与写入竞态）                                                   | R04 · 项目事实 |
| 11  | 把「4 策略检索消融」说成「模型选型实验」         | 前者是 ablation（Recall@5/MRR），跨模型 A/B 需另做对照                                                         | R05            |
| 12  | 现场编造「改造前分数」                           | `rag_eval.json` 是运行时产物且未归档；如实说重跑同数据集对比                                                   | R05            |
| 13  | 声称意图分类用了某参数量级小模型                 | `INTENT_MODEL` 未配置、回落 chat 组 `deepseek-flash`；API 模型无参数规模                                       | R05            |
| 14  | 把检索证据塞进 system prompt                     | 项目放在当前用户消息之后的 **turn-ctx user 消息**，为保住前缀缓存                                              | R05            |
| 15  | 把「读过同类源码」说成「做过方案选型 benchmark」 | 有 Claude Code / Pi / LangChain / LangGraph 源码调研，但无正式选型对比表与实验                                 | R06            |
| 16  | 拿 99.4%→9.5% 当「输入 token 降低」的证据        | 那是 tools 数组追加一个工具导致 cache 命中率掉落的单次实测，只解释设计动机                                     | R06            |
| 17  | 现场给「写入率提升 X%」                          | 仓库无 eval/bench 脚本、无 baseline、无报告；先澄清写入率口径（cache / 记忆 / 会话）                           | R06            |
| 18  | 把「告警归属率」当项目已落地的指标               | 知识库无该指标记录；框架可讲，但须标为推导，别讲成做过的量化治理                                               | R07            |
| 19  | 用 `Range` 回答「上传续传」                      | `Range`/`206`/`Content-Range`/`If-Range` 是 GET 下载语义；上传续传要 `PATCH + Content-Range`、tus 或应用层分块 | R07            |
| 20  | 认为虚拟滚动减少了传输量                         | 它只减少 DOM 节点；传输量靠服务端分页与字段裁剪                                                                | R07            |
| 21  | 用并查集判等待图有环                             | 等待图是**有向图**，须用 DFS 三色 / Kahn 拓扑 / Tarjan SCC                                                     | R07            |
| 22  | 编「我们对比过多种分块长度」                     | 400/60/10 是 `buildChunks` 的源码默认常量，无配置化、无消融实验                                                | R08            |
| 23  | 现场报 rerank 提升幅度                           | 报告未归档；只能讲 4 策略消融机制与 `RERANK_API_KEY` 开关式对照                                                | R08            |
| 24  | 把 SSE 当成降低 TTFT                             | SSE 只让已生成的字尽早出现；TTFT 由前置串行链路与 prefill 决定                                                 | R08            |
