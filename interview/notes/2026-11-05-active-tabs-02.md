## 一、腾讯微信后端一面 · 可见 14 题知识点

### 1. MCP 相关（Q1–Q3）

| #   | 题                                      | 提炼要点                                                                                                                                                                                                                                                                                                                       |
| --- | --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1   | MCP 是什么、底层协议、有哪几种模式      | 定位 = AI 应用与外部工具/数据源之间的**标准化中间层**，把「每个应用自己写胶水代码连 DB/文件系统/第三方 API」变成可插拔挂载。底层 **JSON-RPC 2.0**，传输走 stdio 或 SSE 类长连接（原帖表述见下方校正）                                                                                                                          |
| 2   | 用过 Skills 吗                          | Skills 是 MCP **上层的能力抽象**：MCP 定义「怎么连」，Skills 定义「能做什么」。例：GitHub Skill 封装「建仓库 / 提交代码 / 建 PR」一组操作，Agent 发一条指令即可，不必自己组合多个底层调用。一句话：**对外接口标准化 vs 对内能力模块化**                                                                                        |
| 3   | MCP tool 与普通 function calling 的区别 | ① **执行主体**：function calling 只负责「决定调哪个 + 生成参数 JSON」，执行在调用方服务端；MCP tool 由 Server 端执行 ② **发现机制**：function calling 静态注册、事先写死；MCP tool 可**动态发现**（Server 启动时/建连时告知提供哪些 tool）③ **协议**：function calling 各厂商各一套（OpenAI/Anthropic/Google），MCP 是统一协议 |

:::danger ⚠️ 事实校正（面试别照抄原帖）
原帖把 MCP 模式列成 **「stdio / SSE / Memory」三种**，并说「MCP 的 tool 在 Server 端**自动**执行」。以本仓库事实为准：

- `content/docs/yukino/mcp.md` 记载的是 **JSON-RPC 2.0 + `stdio` / `streamable http` / `sse` 三种传输**；**`Memory` 不是传输模式**，它是资源/能力范畴（可对照 `content/fe/yukino-mcp.md`、`content/docs/mcp-app.md`）。现行 MCP 规范也已用 Streamable HTTP 取代早期 HTTP+SSE。
- 工具调用是 **Host/Client 发起 → Server 执行**，不是「自动执行」；且 Server 返回的工具描述、资源与错误信息都**不可信**，Host 仍需 Schema 校验、权限判断与输出清洗（呼应第一轮摘录 Q11）。
  :::

### 2. Linux 基础（Q4–Q8）

| #   | 题                   | 提炼要点                                                                                                                                                                                                                                                 |
| --- | -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 4   | 进程 / 线程 / 协程   | **进程** = 资源分配最小单位，独立内存空间、fd 表、页表；**线程** = CPU 调度最小单位，同进程共享内存但各有栈与寄存器；**协程** = 用户态轻量线程，程序自己调度、不经过内核                                                                                 |
| 5   | 并行 vs 并发         | 并发是**逻辑同时**：单核靠时间片轮转，同一时刻只有一个任务在跑；并行是**物理同时**：需多核/多 CPU，同一时刻确实多个任务在跑                                                                                                                              |
| 6   | 代码执行时的内存分布 | 高→低地址：**栈**（局部变量/调用帧/返回地址，向下增长）→ 空闲区 → **堆**（malloc/free，向上增长）→ **BSS**（未初始化全局/静态，默认 0）→ **data**（已初始化全局/静态）→ **text**（机器指令，只读）；字符串字面量在 `.rodata`                             |
| 7   | 数据段存什么         | `.data` = 已初始化且非 0 的全局/静态变量（`int global = 42`、`static int s = 100`）；未初始化的进 `.bss`；`const char* s = "hello"` 的 `"hello"` 在 `.rodata`                                                                                            |
| 8   | malloc / free 原理   | 底层 `brk()` 调堆顶 / `mmap()` 映射匿名页（原帖给的小内存阈值 128KB）；空闲块用**空闲链表/伙伴系统**维护；`free` 后 glibc **不一定归还 OS**，而是放回空闲链表供下次复用；块头 `struct malloc_chunk` 记录大小与空闲标志，`free(p)` 靠 `p − 偏移` 找到头部 |

> 关联：Chrome 另有 `tcmalloc` 搜索标签，可作为 malloc 实现的延伸（glibc ptmalloc vs tcmalloc vs jemalloc）；本轮未展开。

### 3. 进程通信（Q9–Q10）

| 方式               | 特点 / 代价                                               |
| ------------------ | --------------------------------------------------------- |
| 管道 `pipe` / FIFO | 简单、字节流无格式；匿名管道限亲缘进程，有名管道可无亲缘  |
| 消息队列           | 有格式、支持优先级，但内核有大小限制                      |
| **共享内存**       | **最快**（用户态直接访问，免去内核/用户态拷贝）；代价见下 |
| 信号量             | 只做同步，不传数据                                        |
| Socket             | 可跨机，灵活但开销大                                      |
| 信号               | 异步通知，只能带极少信息                                  |

共享内存四大缺点：**同步问题**（并发写需信号量/锁）、**管理复杂**（申请释放需所有进程协调）、**大小固定**（扩容要重建）、**安全性**（能访问的进程都能读写）。

### 4. IO 与网络基础（Q11–Q14）

| #   | 题                     | 提炼要点                                                                                                                                                                          |
| --- | ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 11  | IO 多路复用            | `select`：fd 集合有上限（1024）、每次全量遍历、效率随 fd 数线性下降；`poll`：链表无 1024 限制，但仍全量遍历；**`epoll`**：事件驱动、只返回就绪 fd，红黑树管 fd + 双向链表就绪队列 |
| 12  | OSI 七层 / TCP-IP 四层 | 七层：物理 / 数据链路 / 网络 / 传输 / 会话 / 表示 / 应用；四层：网络接口 / 网际 / 传输 / 应用。对应：四层应用层 ≈ 七层应用+表示+会话，网络接口层 ≈ 物理+数据链路                  |
| 13  | TCP vs UDP             | TCP 面向连接、可靠、有序、有流量与拥塞控制，开销大；UDP 无连接、不可靠、无序，轻量快速                                                                                            |

## 二、MySQL 页 · 前 12 题正文要点（补第一轮只有标题索引的缺口）

| #   | 题                         | 核心结论                                                                                                                                                                                           |
| --- | -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | NoSQL vs SQL               | SQL = 关系型、行列二维表、结构化数据（MySQL/PG/Oracle/SQL Server）；NoSQL = 文档/哈希等非二维表（MongoDB/Redis）。选型看 **ACID vs BASE**、数据结构与扩展方式                                      |
| 2   | 三大范式                   | 1NF 列不可再分（原子性）；2NF 在 1NF 上消除**非主属性对主码的部分函数依赖**（针对联合主键）；3NF 消除传递依赖                                                                                      |
| 3   | 连表查询                   | `INNER JOIN`（匹配行）、`LEFT/RIGHT JOIN`（外连接）、`FULL JOIN`                                                                                                                                   |
| 4   | 避免重复插入               | ① `UNIQUE` 约束，重复则报错；② `INSERT ... ON DUPLICATE KEY UPDATE` 冲突时改更新                                                                                                                   |
| 5   | CHAR vs VARCHAR            | `CHAR` 定长补空格（读取去尾部填充）、适合定长；`VARCHAR` 变长 + 1~2 字节记长度、适合不定长；**括号里的长度是字符数不是字节数**，多字节字符集下尤其要注意                                           |
| 6   | VARCHAR(10) 是字节还是字符 | **字符数**。ASCII 下最多 10 字节，`utf8mb4` 下每字符最多 4 字节 → 最多 40 字节                                                                                                                     |
| 7   | int(1) vs int(10)          | **只是显示宽度**，存储恒 4 字节、范围不变；仅在 `ZEROFILL` 时补前导零                                                                                                                              |
| 8   | TEXT 能无限大吗            | 不能：`TINYTEXT 255B` / `TEXT 64KB` / `MEDIUMTEXT 16MB` / `LONGTEXT 4GB`（按**字节**计，utf8mb4 下中文更少吃字符数）；还受 `max_allowed_packet`、内存与传输成本限制，大文件宜放对象存储、DB 存地址 |
| 9   | 金额为何用 DECIMAL         | `FLOAT/DOUBLE` 是近似值，会出对账误差；`DECIMAL(10,2)` 精确十进制（总 10 位、小数 2 位）；也可用 `BIGINT` 存「分」。**应用层计算也要用精确类型并明确舍入规则**                                     |
| 10  | IP 地址怎么存              | IPv4 是 32 位；可 `VARCHAR(15)` 存点分十进制，也可用整数存储（原帖前半部分可见）                                                                                                                   |
| 11  | 外键约束                   | 维护表间引用完整性，避免子表引用不存在的父记录；多对多要用中间选课表，不能只在学生表放 `course_id`                                                                                                 |
| 12  | IN vs EXISTS               | 都用于子查询：`IN` 判断左值是否在右侧集合/结果集；`EXISTS` 判断子查询是否返回行（后半段被截断）                                                                                                    |

> ⚠️ 这是**前 12 题**；索引（40+）、事务（17）、锁（9）、日志（16）、性能调优（7）、架构（2）等板块仍未展开。其中「锁 → MySQL 为什么会死锁」与 [R07 Q6/Q7](../rounds/round-07.md) 直接呼应。

## 四、速记卡

- **MCP**：JSON-RPC 2.0；传输是 stdio / Streamable HTTP / SSE，**没有「Memory 模式」**；Host 发起、Server 执行、Host 校验。
- **Skills vs MCP**：一个定义「能做什么」，一个定义「怎么连」。
- **malloc**：小内存 `brk` 推堆顶、大内存 `mmap`；`free` 多进空闲链表而非立刻还 OS；块头记录大小。
- **epoll**：红黑树管 fd + 就绪链表，只返回就绪 fd；`select` 有 1024 上限且全量遍历。
- **MySQL**：`VARCHAR(n)` 是字符数、`int(n)` 是显示宽度、`TEXT` 按字节分四档、金额用 `DECIMAL` 或整数分。
- **答题纪律**：面经是**别人的答案**，与项目源码事实冲突时以 `content/` 为准，并主动点出差异。
