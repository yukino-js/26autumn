## 二、Redis + MQ 一致性（5、9–13，本面核心）

| 题                                                           | 要点                                                                                                                                                                                                                                                                                                                            |
| ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Redis ZSet 底层是什么**                                    | 小数据量用 **listpack**（旧版 ziplist），元素多/成员长时转 **跳表 skiplist + 哈希表**；跳表支持 `O(log N)` 按 score 范围查询，哈希表保 member→score 的 `O(1)`。阈值由 `zset-max-listpack-entries` / `-value` 控制。排行榜用 `ZADD / ZREVRANGE / ZRANK`                                                                          |
| 缓存扣减命令具体是哪个                                       | 原子扣减：`DECR` / `DECRBY`，或 `INCRBY` 负值；判断库存不能先 `GET` 再 `DECR`（竞态）。更稳的是 **Lua 脚本**把「判库存 + 扣减 + 记录用户」打包成一次原子调用（对应面经 10「Redis + Lua 解决一人一单与超卖」）                                                                                                                   |
| 加锁兜底是干嘛                                               | Lua/原子命令之外的并发保护：分布式锁（SET NX PX + 唯一 value + Lua 释放）或 DB 乐观锁；防止重复扣减、重复发奖、并发重建缓存。**注意**：有了 Lua 原子扣减就不一定需要锁，要讲清两者各自解决什么                                                                                                                                  |
| Redis 同步更新到数据库怎么实现                               | 先写 Redis 抗并发 → 发 MQ 消息 → 消费者幂等落库（唯一键/去重表）→ 失败重试 + 死信；**不是同步双写**（双写有一致性窗口与失败回滚问题）                                                                                                                                                                                           |
| 抽奖结果何时通知用户                                         | 追问「具体节点」：是发 MQ 时就通知、还是落库完成后发短信/邮件？正确姿势是**落库成功且事务提交后再通知**，避免「用户收到中奖通知但库里没有」；通知本身要幂等、可重放                                                                                                                                                             |
| **Redis 先扣减、MQ 更新 DB，如何保证一致性？消息丢了怎么办** | 分层答：① 生产者侧 **本地消息表 / outbox**（Redis 扣减与消息落库在同一事务域）或事务消息；② Broker `acks=all` + `min.insync.replicas`；③ 消费侧**业务唯一键幂等 + 处理成功后提交 offset**；④ 对账任务定时比对 Redis 扣减流水与 DB 记录并补偿；⑤ 死信队列 + 告警。**至少要承认「Redis 与 DB 之间只能是最终一致」**，别声称强一致 |
| 压测工具是什么                                               | 准备具体工具与指标：wrk / JMeter / k6 / Locust；看 QPS、P95/P99、错误率、Redis/DB 连接池水位、MQ lag；说明怎么造数据、怎么排除客户端瓶颈                                                                                                                                                                                        |

> 项目互证：`content/docs/tiktok.md` 的 Kafka **至少一次**语义、位点在业务成功后提交、幂等去重、`ReplacingMergeTree(version)` / `row_number()` 存储层收敛、积压定位（lag + 消费 RT + MySQL 锁等待）；`content/be/redis.md` 的 ZSet 结构与 `SET NX PX` 原子锁（禁 `SETNX`+`EXPIRE` 两条命令）。这两篇能直接支撑上述答案。

## 三、八股（4、14–19）

| 题                         | 要点                                                                                                                                                                                                                                    |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 数据库隔离级别、哪些日志   | 读未提交 / 读提交 / **可重复读（InnoDB 默认）** / 串行化；日志 `redo log`（崩溃恢复）、`undo log`（回滚 + MVCC）、`binlog`（复制/归档）、`relay log`、慢查询/error log。详见 [11-05 第四轮 MySQL 补抓](../2026-11-05-active-tabs-04.md) |
| 计算机网络分层             | OSI 七层 / TCP-IP 四层对应关系（[11-05 第二轮](../2026-11-05-active-tabs-02.md) 已记）                                                                                                                                                  |
| 三次握手                   | SYN → SYN-ACK → ACK；为什么不是两次（防历史重复连接初始化、同步双方序列号）；四次挥手与 TIME_WAIT                                                                                                                                       |
| Java 内存分区              | 堆（新生代 Eden/S0/S1 + 老年代）、方法区/元空间、虚拟机栈、本地方法栈、程序计数器；JDK8 后元空间用本地内存                                                                                                                              |
| GC 算法                    | 标记-清除 / 复制 / 标记-整理；分代收集；CMS / G1 / ZGC 的取舍（停顿目标、Region、并发整理）                                                                                                                                             |
| **最长不含重复字符的子串** | 滑动窗口 + 哈希表记字符上次位置；右指针扩展、遇重复时左指针**只能右移不回退**；`O(n)` 时间、`O(min(n, 字符集))` 空间                                                                                                                    |
