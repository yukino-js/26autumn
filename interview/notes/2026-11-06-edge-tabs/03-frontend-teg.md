## 二、浏览器与框架（6、8、12–15、17、20）

| 题                                     | 要点                                                                                                                                                                                                                                                                                                            |
| -------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **URL 输入到页面渲染**                 | DNS → TCP → TLS → HTTP → 解析 HTML 建 DOM / CSSOM → 执行 JS → 布局 → 绘制 → 合成；`DOMContentLoaded` 不等图片、`load` 等全部资源。项目事实见 `content/fe/fe.md`（含 HSTS、缓存、HTTP/2 多路复用）                                                                                                               |
| **mini-React 的难点**                  | Fiber 可中断渲染、双缓冲、调和（reconciliation）、hooks 链表与依赖比较、批量更新与优先级调度                                                                                                                                                                                                                    |
| **Diff 算法原理与 v16 前后复杂度变化** | 传统树编辑距离 `O(n³)`；React 用三条启发式（**不同类型节点直接替换、同层比较、key 标识稳定元素**）降到近似 **`O(n)`**。v16 引入 **Fiber**，把递归栈式调和改成可中断的链表遍历，复杂度仍是 O(n)，**变化的是「可中断/可分片」而不是量级**——这题问的「时间复杂度变化」容易设陷阱，要先澄清是比较复杂度还是调度模型 |
| Diff 的遍历与比较过程                  | 深度优先、同层双指针；key 命中则复用并移动，未命中则新建/删除；`lastPlacedIndex` 决定是否需要移动                                                                                                                                                                                                               |
| Vue 了解吗                             | 响应式（Proxy / defineProperty）、模板编译、组件与组合式 API；与 React 的「可变数据 + 依赖追踪」vs「不可变 + 重新渲染」对照                                                                                                                                                                                     |
| **如何处理错误状态**                   | 错误边界（Error Boundary）捕获渲染/生命周期错误、`try-catch` 处理事件与异步、`unhandledrejection` 监听、兜底 UI 与重试、错误上报（可对照 `content/fe/yukino-sentry.md` 的 JSONL 日志与 sourcemap 反解、`content/docs/data.md` 的 JSError 数据模型与 rrweb 现场还原）                                            |
| **JS 原型链**                          | 对象 `__proto__` → 构造函数 `.prototype` → `Object.prototype` → `null`；属性查找沿链向上；`new` 的四步；`instanceof` 本质是查原型链；ES6 class 是语法糖                                                                                                                                                         |
| 管理系统封装了哪些自定义 hook          | 准备 2–3 个能讲清依赖与清理的真实例子：请求状态（竞态取消）、分页/筛选、权限、防抖、WebSocket 订阅；说清为什么抽、如何处理卸载与竞态（可对照 `content/fe/tanstack.md`、`fetchpriority-swr.md`）                                                                                                                 |

## 三、网络与安全（18–19）

**HTTPS 原理**：TLS 握手（证书校验 → 非对称加密协商/交换密钥 → 对称密钥加密后续通信）、HTTP over TLS、CA 链与证书校验、TLS 1.3 1-RTT / 会话复用 0-RTT、HSTS。

**HTTPS 解决三个问题**：**机密性**（防窃听）、**完整性**（防篡改）、**身份认证**（防冒充）。⚠️ 不解决：服务端被入侵、客户端恶意、DNS 劫持前的最初重定向、证书误签发（需 HSTS/证书透明/HPKP 已废弃等配合）。

> 与 [R03 CSRF/Cookie](../../rounds/round-03.md) 是同一套 Web 安全知识域，可一起复习。
