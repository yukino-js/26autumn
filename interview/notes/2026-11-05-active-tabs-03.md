## 四、MySQL 页 · 索引 / 事务板块正文要点（补前两轮）

| 题                       | 核心结论                                                                                                                                                                                                                       |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 聚簇 vs 非聚簇索引       | 聚簇索引 **B+ 树叶子节点存完整数据行**，索引即数据；二级索引叶子存索引列 + 主键值，查非索引列要拿主键回聚簇索引 → **回表**。每表只有一个聚簇索引                                                                               |
| 主键是聚簇索引吗         | InnoDB 是；无主键取第一个「所有索引列 NOT NULL 的唯一索引」，再没有则生成 **6 字节隐藏 row ID**。有序是逻辑顺序，不代表磁盘页连续                                                                                              |
| 聚簇索引数据更新         | 更新主键 → 排序位置变且二级索引里的主键值也要维护；更新二级索引列 → 只调二级索引；更新普通列若变长导致页空间不足，仍可能记录迁移/页分裂/页外存储                                                                               |
| 索引失效                 | **左模糊** `LIKE '%xx'`、对索引列**用函数或计算** `YEAR(created_at)=2024` / `price+1=10`、**隐式类型转换**（VARCHAR 列传数字）；`LIKE 'xx%'` 可走范围扫描，MySQL 8.0 函数索引可服务匹配表达式                                  |
| 索引下推 ICP vs 覆盖索引 | ICP 把可用索引列判断的条件**下推到存储引擎先过滤再回表**（执行计划 `Using index condition`）；覆盖索引是**索引已含查询所需全部列、完全不回表**                                                                                 |
| 回表 / 覆盖索引          | 二级索引叶子只有索引列 + 主键；所需列都在索引里即覆盖索引，减少数据页 I/O                                                                                                                                                      |
| 四个隔离级别             | 读未提交 / 读提交 / **可重复读（InnoDB 默认）** / 串行化；RR 下普通快照读复用第一次快照读建立的快照                                                                                                                            |
| RR 下 A 提交 B 能看见吗  | 看**快照是否建立**与**快照读 vs 当前读**：B 已建快照且 A 在其后提交 → 沿 undo 版本链读旧版本；B 只 `BEGIN` 未快照读、A 先提交 → 建快照时可见；`SELECT ... FOR UPDATE` 当前读不复用旧快照，遇冲突锁等待；B 自己改过的对自己可见 |

> 仍未展开：日志（redo/binlog 两阶段提交）、性能调优（EXPLAIN、深分页）、架构（主从延迟）。

## 六、速记卡

- **真题按组来**：面经 04 / 06 / 08 分别就是已练的第一轮摘录 / R08 / 第二轮摘录；同一岗位同一天会有多套题。
- **量化追问是主线**：QPS 怎么统计、提升指标怎么算、baseline 是谁、效果对比怎么做、置信度阈值怎么定——答不出「口径」比答不出「数字」更致命。
- **MySQL 索引**：聚簇叶子存整行、二级索引叶子存主键、回表 = 再查一次聚簇；ICP 少回表、覆盖索引不回表；失效三件套 = 左模糊 / 函数计算 / 隐式转换。
- **RR 可见性**：不取决于谁先 `BEGIN`，取决于**快照建立时机**与**快照读还是当前读**。
