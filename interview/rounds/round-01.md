## Q1 · Coding Agent 的执行链路（D1 / D2）

> 你在做一个能改代码的 coding agent（类似 Claude Code）。用户下达任务：
> **「给这个仓库的所有 API 加上鉴权中间件」**。
>
> 请描述从用户输入到最终落盘改动的**完整执行链路**，并回答：
>
> - **(a)** 上下文怎么组织、怎么裁剪，仓库很大时如何避免塞爆窗口？
> - **(b)** tool-call 循环靠什么终止？如何防止死循环和「反复改同一处」？
> - **(c)** 工具执行失败、或批量修改只成功一部分时，怎么恢复？
> - **(d)** 怎么防止它改坏不该改的文件？

**考察点**：Agent loop、上下文工程、检索 vs 全量灌入、终止条件、状态与幂等、权限边界、人在回路。

**追问链**：MCP 在这条链路里扮演什么角色，和直接 function calling 有何区别？工具权限确认该放在哪一层？

## Q2 · 多租户 LLM 网关（D4）

> 设计一个**多租户 LLM 网关**：支持流式输出（SSE）、多模型路由、按租户限流、超时与重试、按 token 计费。
>
> 请给出核心组件与一次请求的数据流，并回答：
>
> - **(a)** 客户端断连后，后端怎么止损、避免继续烧 token？
> - **(b)** 重试如何避免重复计费与非幂等的副作用？
> - **(c)** 流式返回中途模型报错，怎么把「已生成的部分」和「错误」一起交给前端？
> - **(d)** token 计量放在哪一层才准？

**考察点**：SSE 语义、取消传播、背压、幂等键、限流算法、错误分帧、计量口径、可观测性。

**追问链**：SSE vs WebSocket 如何取舍？多模型路由的 fallback 怎么设计才不放大故障？

## Q3 · 流式对话前端（D5）

> 实现一个 ChatGPT 式对话页：**流式渲染 Markdown + 代码块**、可**中途停止生成**、**切换会话再切回来不丢消息**、**刷新页面能续上**。
>
> 请说明状态怎么分层、流式数据怎么进 React 状态而不卡顿，并回答：
>
> - **(a)** 为什么不能简单地逐 token `setState` 追加？替代方案是什么？
> - **(b)** TanStack Query / SWR 在这套方案里该用在哪一层，**哪里不该用**？
> - **(c)** 点「停止」后服务端可能还在跑，前端如何保证不出现「幽灵消息」？
> - **(d)** 乐观更新失败怎么回滚？

**考察点**：状态分层（server state vs client state）、批处理与背压、AbortController、请求与会话的解耦、缓存失效。

**追问链**：如何做代码块的流式语法高亮而不反复重解析整个文档？
