## 三、HR 面怎么讲「你为什么适合这个岗位」

### 30 秒版（HR 面标准答案）

> 这个岗位要的是「Agent 原理 + RAG + 全栈工程 + 评测」，我四条都有可验证的证据：Agent 内核我自己写了开源的 `yukino-code`，多 Agent 协作、记忆压缩、工具调用、权限沙箱都实现过；RAG 我在阿里做了双路召回加 reranker，`recall@5` 到 98%；全栈我三段实习前端、后端、native 都交付过；评测我建了 500 题评估集，误放率 0%。所以我不是「学过 Agent」，是「把 Agent 从能聊做到能上线」。

### 90 秒版（按 JD 四条职责展开）

> 我对照 JD 的四条职责说：
>
> **第一，多 Agent 协作与工具调用。** 我在开源项目 `yukino-code` 里实现了 subagent（定义式和 fork 式、前台同步和后台异步）、Agent Team（文件邮箱 + p2p/broadcast 通信）、MCP 工具延迟加载和权限沙箱。这正是 JD 说的「多 Agent 协作框架、任务规划与调度、工具调用与执行引擎」。
>
> **第二，记忆与推理链路。** `yukino-code` 有两层上下文压缩、Auto-Dream 自动记忆提取；阿里那边我做了指代消解 → query 扩写 → 意图识别 → 分流状态机的推理链路，用 LangGraph4j 编排 8 类意图到 5 个出口。
>
> **第三，评测与质量保障。** 这是我最想强调的——很多 Agent 项目缺评测。我建了 500 题五桶评估集，`recall@5 98%`、幻觉率 0.7%；置信度门控误放率 0%、误拦率 17%；`yukino-code` 用 SWE-bench-Live 做自动化评测，Prompt Cache 命中率 >90% 控成本。
>
> **第四，前沿跟踪与落地。** 我把 A2UI、MCP Apps、Claude Code、LangGraph 都做了源码级调研，写在 `content/docs/`，并且都落到了项目里，不是只读不用。

**采分点：** 每句都扣 JD 原文的词（「多 Agent 协作」「评测与质量保障」「技术预研与落地」），让 HR 听得出「你研究过这个岗位」。**雷区：** 只说「我会 Agent」，不给 JD 对应的证据。

| 评测体系          | 「误放率 0% 是不是样本太少？」          | 结论：口径是 450 道可回答题。证据：500 题五桶评估集，门控把错误承诺拦在生成前。边界：误拦 17% 是代价，下一步降误拦。                                                 |
| LangGraph         | 「你用过 AutoGen/CrewAI 吗？」          | 结论：LangGraph 系我实战过，AutoGen/CrewAI 我读过没落地。证据：LangGraph4j + LangGraph 两个项目。边界：框架是工具，原理我通。                                        |
| RAG / 知识图谱    | 「知识图谱你做过吗？」                  | 结论：向量检索和双路召回我做过，知识图谱没实战。证据：RAG + BM25 + RRF + reranker、Milvus。边界：知识图谱是我下一步想补的。                                          |
| 全栈              | 「你前端强还是后端强？」                | 结论：主线是 Agent 工程化 + 服务端，前端能独立交付。证据：监控 SDK、虚拟滚动、模块联邦（前端）；连接池、数据链路、WANProxy（后端）。边界：不把自己包装成纯前端专家。 |
| AI 编程工具       | 「你用 AI 写代码，那你自己会写吗？」    | 结论：会，且我知道 AI 的边界。证据：腾讯批量迁移用「规范先行 + 人工把关高风险点」，不是无脑托管。边界：依赖数组、竞态、setState 语义这些必须人工 review。            |
| 分布式 / 消息队列 | 「Kafka 你怎么保证不丢消息？」          | 结论：至少一次 + 幂等去重。证据：字节用本地消息表保证 DB 与 MQ 一致性，消费端幂等写。边界：这是链路设计，不是我独立造 Kafka。                                        |

## 四、JD 专属压力题与练习题

### 压力题（基于 JD 的质疑）

**P1「你简历写得很全，但 JD 要的 AutoGen/CrewAI/MetaGPT 你都没用过，是不是不匹配？」**

- 意图：测「面对 JD 差距的反应」。
- 应对：承认差距 + 给可迁移证据 + 给补齐动作。
- 参考：「JD 列的四个框架我实战的是 LangGraph 系（LangGraph4j 和 LangGraph 两个项目），AutoGen/CrewAI/MetaGPT 我读过设计但没落地。但框架是工具，**底层都是 Planning、Memory、Tool Use、Reflection 这套机制**，我在 `yukino-code` 里是自己实现的，所以换框架对我是迁移不是从零。如果岗位需要，我可以一周内上手。」
- 雷区：「我都用过」（撒谎）；「框架不重要」（轻视 JD）。

**P2「AI 全栈工程师要会推理部署，你只做过调用侧，是不是不够格？」**

- 意图：测「短板的诚实度」。
- 应对：诚实承认 + 给相邻证据 + 给学习路径。
- 参考：「推理部署（模型并行、量化、serving）我确实没独立做过，我更多在调用侧和工程链路。但我理解部署的约束——比如 Prompt Cache 命中率 >90% 就是为了控推理成本，置信度门控也是为了减少无效调用。如果岗位需要部署能力，我会从 [vLLM/TensorRT-LLM] 这类入手补，我有 native 和性能优化的底子（腾讯 Valgrind、字节 profiling），补部署比纯应用层的人快。」
- 雷区：「我什么都会」（不可信）；「我不会」（直接出局）。

**P3「你这些 Agent 项目都是个人/开源的，没有真实业务验证，能上生产吗？」**

- 意图：测「个人项目 vs 生产系统」的认知。
- 应对：区分个人项目与生产项目 + 给生产证据。
- 参考：「我分两类说：`yukino-code` 确实是个人开源项目，但它是我理解 Agent 内核的方式，不是用来替代生产系统的。**真正的生产验证在阿里**——经营托管 Agent 已经在淘宝商家端落地，服务真实商家，误放率 0% 就是生产口径；腾讯的管理端是内部生产系统，内存泄漏修复是线上事故。所以我有『个人项目证明深度 + 生产系统证明落地』两条线。」
- 雷区：把个人项目说成有海量用户（穿帮）。

**P4「JD 要求代码质量意识强，你用 AI 批量生成代码，质量怎么保证？」**

- 意图：测「AI 辅助 vs 代码质量」的平衡。
- 应对：给「人工把关」的具体机制。
- 参考：「我用 AI 但不是无脑托管。腾讯迁移五类选择器时，我的做法是 **规范先行 + 单组件迁移 + TDD + 小步提交**：先把生命周期映射、竞态处理写成规范喂给模型，第一个组件人工精修做 few-shot，然后聚焦 review 高风险点（依赖数组、过期闭包、请求竞态、setState 合并语义），每个组件迁移前后跑回归，出问题单独回滚。**AI 加速机械翻译，人保证语义正确**，这才是代码质量意识。」
- 雷区：「AI 生成的我直接用」（质量意识差）。

### 练习题（JD 匹配自测）

> 练习方法：遮住「答案要点」，出声答，录音，对照自评。每题 60–90 秒。

**J1 你为什么适合 Agent 开发工程师这个岗位？**

- 要点：用 [30 秒版](#30-秒版hr-面标准答案) 或 [90 秒版](#90-秒版按-jd-四条职责展开)。扣 JD 四条职责，每条给一个证据。
- 评分：① 扣 JD 原文的词；② 每条职责有可验证证据；③ 不超 90 秒；④ 不空泛。

**J2 JD 要求熟悉 LangGraph/AutoGen/CrewAI/MetaGPT，你用过哪些？**

- 要点：诚实说 LangGraph 系实战（LangGraph4j + LangGraph），其他读过没落地；底层机制相通。
- 评分：① 不撒谎；② 给可迁移证据；③ 给补齐动作。

**J3 JD 要求 RAG 和知识图谱，你做过吗？**

- 要点：RAG 双路召回 + RRF + reranker + Milvus 做过；知识图谱没实战，是下一步。
- 评分：① 区分「做过」和「没做过」；② RAG 有具体口径；③ 不装懂知识图谱。

**J4 AI 全栈工程师要会推理部署，你的差距在哪？**

- 要点：诚实承认调用侧为主；给相邻证据（Prompt Cache 控成本、性能优化底子）；给学习路径。
- 评分：① 诚实；② 有相邻能力证据；③ 有具体补齐计划。

**J5 你的个人项目能证明你能上生产吗？**

- 要点：区分个人项目（深度）与生产系统（阿里淘宝商家端、腾讯内部系统）；两条线。
- 评分：① 不把个人项目说成生产；② 给真实生产证据；③ 区分清楚。

**J6 JD 要求「熟练使用 AI 编程工具」，你怎么保证代码质量？**

- 要点：规范先行 + few-shot + 人工把关高风险点 + TDD + 小步提交。
- 评分：① 有具体机制；② 体现「人保证语义」；③ 不显得依赖 AI。

## 六、基于 JD 的反问

HR 面反问环节，用 JD 提问能体现「你认真研究过岗位」。推荐问：

1. **岗位侧重：** 「JD 里 Agent 开发工程师和 AI 全栈工程师的职责有重叠，请问这个团队更偏 Agent 内核（编排/记忆/评测）还是偏业务全栈落地？」——体现你读过两个 JD。
2. **部门方向：** 「我意向的部门是 `[元宝/腾讯营销/企业微信/TEG 混元]`，请问这个部门的 Agent 主要解决什么业务问题？」——体现你研究过部门。
3. **评测体系：** 「JD 提到『搭建 Agent 评测与质量保障体系』，请问团队现在的评测是怎么做的？有没有现成的评估集和指标？」——体现你懂 Agent 的难点在评测。
4. **技术栈：** 「团队现在主要用哪个 Agent 框架？是 LangGraph 系还是自研？」——体现你关心落地细节。

**不要问：** 薪资、加班、能不能远程、「我表现怎么样」（这些见 [反问清单](/interview/hr/close-and-compensation#反问清单)）。
