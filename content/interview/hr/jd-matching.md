## 一、官方 JD 原文

### 岗位 A：AI 全栈工程师（技术类 · 主投）

- **来源：** [join.qq.com/post_detail.html?postid=1282707398326592512](https://join.qq.com/post_detail.html?postid=1282707398326592512)
- **招聘项目：** 应届毕业生 ｜ **面试城市：** 远程面试
- **工作城市：** 深圳总部、北京、上海、广州、成都、杭州
- **CSIG 意向部门：** **腾讯云-技术与产品方向**、腾讯会议、WorkBuddy/CodeBuddy 系列智能体产品、QQ 浏览器、ima、腾讯文档

**岗位职责（原文）：**

> 1、负责产品业务系统的全栈开发，涵盖前端交互、后端服务、数据存储等，参与需求分析、架构设计、开发交付与迭代优化；
> 2、构建基于大模型的全链路应用系统，包括 AI 能力接入、Agent 架构设计、RAG 系统搭建、业务知识库建设等，实现端到端的 AI 应用落地；
> 3、跟踪 AI 与全栈技术的前沿发展，关注行业前沿动态，并结合业务场景进行落地实践。

**岗位要求（原文）：**

> 1、熟练掌握主流前后端技术栈，具备扎实的计算机基础知识和全栈工程能力，能够完成需求分析、方案设计、开发交付及迭代优化的完整流程；
> 2、熟练使用 AI 编程工具，能通过 AI 完成业务开发与应用搭建；
> 3、了解大模型基本原理与推理部署方式，熟悉 RAG 技术、Agent 原理（包括 Tool Use、Planning、Memory 等），有相关实践经验；
> 4、具备系统设计能力，了解分布式系统、微服务架构、消息队列、缓存等后端核心技术；
> 5、对 AI 前沿技术有浓厚兴趣，愿意主动探索 AI 在业务场景的创新应用；
> 6、具备良好的沟通协作与问题解决能力，有较强的责任心，能高效配合团队完成项目交付。

**加分项（原文）：**

> 1、有全栈项目经验（如独立开发过 Web 应用 / SaaS 产品 / AI 应用平台等）；
> 2、具备模型算法调优经验、个人项目、开源项目或成熟业务系统开发经验者优先；
> 3、有 RAG、主流 Agent 框架（如 LangGraph / AutoGen 等）使用经验；
> 4、有复杂 Agent 构建经验，能够系统性评估质量、持续改进效果、优化应用性能/成本；
> 5、参与过开源项目或有技术博客、技术作品；
> 6、在技术竞赛、开源社区中有突出表现。

### 岗位 B：技术产品经理（产品类 · 产品岗主投）

- **来源：** [join.qq.com/post_detail.html?postid=1284317600528245760](https://join.qq.com/post_detail.html?postid=1284317600528245760)
- **招聘项目：** 应届毕业生 ｜ **面试城市：** 远程面试
- **工作城市：** 深圳总部、北京、上海、成都、杭州
- **CSIG 意向部门：** **腾讯云-技术与产品方向**、腾讯安全、WorkBuddy/CodeBuddy 系列智能体产品、腾讯地图

**岗位职责（原文）：**

> 1、负责 toB（或 toG）平台产品的产品策划和运营工作，提供具有竞争力的产品方案，实现产品增长、商业化目标；
> 2、关注行业生态、同类产品动向，结合产品优势制定行业合作和市场运营方案，提升行业影响力；
> 3、持续关注云计算和 AI/大模型发展趋势，理解 AI 在 B 端产品中的应用逻辑（智能客服、AI 数据分析、RAG 知识管理等），基于业界标杆和技术原理的分析，落地技术产品；
> 4、构建业务数据监控体系、IT 支持及客服体系、渠道和营销体系，持续改善系统架构、运营效率和成本，提升销售转化效率；
> 5、进行业务调研和客户反馈收集，提炼通用需求并判断优先级，推进销售或客户的痛点问题持续解决。

**岗位要求（原文）：**

> AI 应用技能：善于借助 AI 工具拆解复杂问题、探索解决方案，并能对 AI 的输出进行高质量判断，具备人机协同的工作意识和习惯。
>
> 专业能力：1、计算机、软件、人工智能、大数据相关专业；2、热爱互联网、热爱技术；对产品策划有激情，热爱思考，具有优秀的逻辑思维和创新能力。
>
> 其他：1、有亲和力，擅于沟通，并有优秀的执行力来保障需求的落地；2、有服务意识，用心满足客户诉求，愿意深入了解客户的应用场景；3、善于面对挑战和质疑。

**加分项（原文）：** 有一定的编程能力者。

### 岗位 D / E：后台开发、前端开发（技术类 · 兜底）

若团队按更传统的技术岗招人，后台/前端开发也能进「腾讯云-技术与产品方向」。两篇 JD 都在 2026 版里明确加了「AI 应用技能」与「用 AI 工具提效」要求，你的匹配点：

- **后台开发**（postId `1282707383965295616`）：要求 C/C++/Java/Go 之一、TCP/UDP 与网络编程、操作系统/数据结构/数据库。对应证据：Go（WANProxy、`yukino.go`）、Node（腾讯管理端）、TCP 连接池与进程池、字节 Kafka/ClickHouse 数据链路。加分项里的「分布式系统、云原生、用 AI 完成项目、大模型 API 集成」你全部命中。
- **前端开发**（postId `1282707439695012865`）：要求 JS/TS/HTML/CSS、React/Vue/Next.js、了解一门后端语言。对应证据：React/TS、`yukino-sentry` 监控 SDK、字节虚拟滚动、阿里 A2UI 与模块联邦。加分项里的「对话式 UI / AI 交互组件、Next.js 项目经验」你全部命中。

## 三、HR 面怎么讲「你为什么适合这个岗位」

### 技术岗 · 30 秒版（AI 全栈工程师标准答案）

> 这个岗位要的是「全栈工程 + Agent 架构 + RAG + 评测」，我四条都有可验证的证据：Agent 内核我自己写了开源的 `yukino-code`，多 Agent 协作、记忆压缩、工具调用、权限沙箱都实现过；RAG 我在阿里做了双路召回加 reranker，`recall@5` 到 98%；全栈我三段实习前端、后端、native 都交付过；评测我建了 500 题评估集，误放率 0%。所以我不是「学过 Agent」，是「把 Agent 从能聊做到能上线」——这正是腾讯云 toB 场景最需要的工程能力。

### 技术岗 · 90 秒版（按 JD 三条职责展开）

> 我对照 JD 的三条职责说：
>
> 第一条「全栈开发」：我三段实习前端、服务端、native、数据链路都交付过——字节做性能采集和 Kafka/ClickHouse 数据链路，腾讯做 Node/native 和 React 迁移，阿里做 workflow 编排加 A2UI 前端。所以「前端交互、后端服务、数据存储」我不是只懂一端。
>
> 第二条「大模型全链路应用」：这是我最强的部分。我在阿里做经营托管 Agent，负责 workflow 加 agent 混合编排、RAG + BM25 双路召回、生成前的置信度校验，项目在淘宝商家端落地，`recall@5` 98%、人工核验幻觉率 0.7%。业余我还自己写了开源 Coding Agent `yukino-code`，Agent 架构、RAG、Tool Use、Memory、上下文压缩都实现过。
>
> 第三条「跟踪前沿并落地」：我 `content/docs/` 里对 Claude Code、Pi、LangGraph、A2UI/MCP 都做过源码级调研，而且不是看完就完，都落成了可运行的东西。
>
> 我理解腾讯云这个方向是把 AI 做成 toB 平台，客户对稳定性、权限、评测的要求最高，这正好是我一直练的工程能力。

### 产品岗 · 30 秒版（技术产品经理标准答案）

> 我理解技术产品经理要做的是「把技术能力策划成客户愿意付费的 toB 产品」。我的优势是**既懂技术原理，又做过产品决策**：在阿里做经营托管 Agent 时，我先定义的不是技术方案，而是「商家到底怕什么」——把「答错引发纠纷」变成误放率、误拦率两个可测指标，架构才顺着定下来，这就是产品口径。同时我能读懂云计算和 AI 的技术原理，做产品判断不会被忽悠。JD 加分项说「有一定编程能力」，我是 Go/TS 双语言加开源项目，远超这条。

### 产品岗 · 90 秒版（按 JD 五条职责挑三条讲）

> 我挑三条最相关的说：
>
> 第一条「toB 平台产品策划」：我在阿里做的经营托管 Agent，本质就是帮商家省客服人力的 toB 能力。我做产品的习惯是**先定义成功和失败的成本**——商家最怕的是「答错引发纠纷」，所以我把它变成误放率 0%、误拦率 17% 两个指标，再反推架构。这是产品思维，不是纯技术思维。
>
> 第三条「理解 AI 在 B 端的应用逻辑」：智能客服、RAG 知识管理这些场景我在阿里都落地过；腾讯云的智能体开发平台 ADP 我也研究过，它按业务复杂度分了 Claw、标准、工作流、Multi-Agent 四种范式，我理解这套设计的关键是「构建—分发—治理」加「被集成」。
>
> 第四条「业务数据监控与成本」：我在腾讯做过前端监控 SDK，在字节做过性能数据链路，懂「怎么用数据看产品健康度」；做 Agent 时我用 Prompt Cache 把成本压下来，懂「怎么算产品的账」。
>
> 所以我的定位是「懂技术原理的技术产品」，能把技术趋势翻译成客户价值和优先级。

**采分点（两版通用）：** 扣 JD 原文的词、每条给可验证证据、不超时、不空泛。**雷区：** 把 90 秒讲成 3 分钟；堆名词不给结果；产品岗却全程讲技术实现、不讲客户价值。

## 五、JD 专属压力题与练习题

:::warning 压力题心法
JD 压力题的本质是「拿 JD 里你没写的那条压你」。应对一律是：**承认 + 可迁移证据 + 补齐动作**，不装全会。详见 [压力面题库](/interview/hr/pressure)。
:::

- **「JD 要求模型算法调优，你是工程背景，是不是不匹配？」**——承认调优偏算法岗；你做的是 Agent 工程化（prompt/检索/评测调优），并给「补过哪些」的证据。
- **「产品岗要商业化目标，你做过增长/转化吗？」**——诚实没直接背过商业化 KPI；但你定过「人力成本下降、误放/误拦」这类**能换算成钱**的指标，口径意识是通的。
- **「你三段实习方向不同，怎么证明你能在腾讯云长期做产品/全栈？」**——回「测量→稳定→自动化」主线，见 [简历叙事](/interview/hr/narrative)。
- **「腾讯云要懂云产品，你用过什么？」**——回 [动机篇的云产品口径](/interview/hr/motivation#业务理解题)：不装精通，讲分层与取舍，给两周补齐计划。

### 练习题（JD 匹配自测）

> 练习方法：遮住「答案要点」，出声答，录音，对照自评。每题 60–90 秒。

**J1 你为什么适合 AI 全栈工程师这个岗位？**

- 要点：用 [技术岗 30 秒版](#技术岗--30-秒版ai-全栈工程师标准答案) 或 [90 秒版](#技术岗--90-秒版按-jd-三条职责展开)。扣 JD 三条职责，每条给一个证据。
- 评分：① 扣 JD 原文的词；② 每条职责有可验证证据；③ 不超 90 秒；④ 不空泛。

**J2 你为什么适合技术产品经理？你不是产品出身。**

- 要点：用 [产品岗 30 秒版](#产品岗--30-秒版技术产品经理标准答案)。核心是「定义误放/误拦指标」这个产品决策 + 「懂技术原理」的差异化。
- 评分：① 讲客户价值不讲技术实现；② 有具体产品决策；③ 把编程能力讲成杠杆而非转行劣势。

**J3 JD 要求 RAG 和知识图谱，你做过吗？**

- 要点：RAG 双路召回 + RRF + reranker + Milvus 做过；知识图谱没实战，是下一步。
- 评分：① 区分「做过」和「没做过」；② RAG 有具体口径；③ 不装懂知识图谱。

**J4 AI 全栈要会推理部署，你的差距在哪？**

- 要点：诚实承认调用侧为主；给相邻证据（Prompt Cache 控成本、性能优化底子）；给学习路径。
- 评分：① 诚实；② 有相邻能力证据；③ 有具体补齐计划。

**J5 产品岗问「云计算和 AI 在 B 端的应用逻辑」，你怎么答？**

- 要点：智能客服/AI 数据分析/RAG 知识管理三类场景 + 腾讯云 ADP 四范式的公开产品理解；区分「看过文档」和「用过」。
- 评分：① 有场景有产品；② 不装实操；③ 能讲「客户为什么付费」。

**J6 JD 要求「熟练使用 AI 编程工具」，你怎么保证代码质量？**

- 要点：规范先行 + few-shot + 人工把关高风险点 + TDD + 小步提交。
- 评分：① 有具体机制；② 体现「人保证语义」；③ 不显得依赖 AI。

## 七、基于 JD 的反问

HR 面反问环节，用 JD 提问能体现「你认真研究过岗位」。推荐问：

1. **岗位侧重：** 「我投的是 AI 全栈工程师，意向腾讯云技术与产品方向，请问这个团队更偏 Agent 平台内核（编排/记忆/评测）还是偏某个云产品业务的全栈落地？」——体现你读过 JD 也研究过部门。
2. **产品 vs 技术：** 「这个方向同时招技术产品经理和 AI 全栈工程师，请问产品和研发在 Agent 平台上的分工是怎样的？我两边都能聊，想确认团队更需要哪种。」——体现你理解「技术与产品」是个组合。
3. **评测体系：** 「JD 提到『系统性评估质量、持续改进』，请问团队现在的 Agent 评测是怎么做的？有没有现成的评估集和指标？」——体现你懂 Agent 的难点在评测。
4. **被集成场景：** 「我研究过腾讯云 ADP 的企业级 OpenAPI，请问团队的 Agent 更多是自有产品，还是被集成到客户的 CRM/工作台里？」——体现你研究过产品形态。

**不要问：** 薪资、加班、能不能远程、「我表现怎么样」（这些见 [反问清单](/interview/hr/close-and-compensation#反问清单)）。
