## 为什么适合：30 秒

> 我同时有实际业务 Agent 和全栈研发经验。在淘天做过经营托管 Agent，个人项目持续实践模型 API、上下文、权限和工具执行；腾讯实习做过 SDK、资源池和故障治理。我也通过实习接触了 Agent 云沙箱。这些经验和团队的 Harness、Managed API、SDK 方向有交集，我希望从具体模块做起，把接入体验和运行质量做好。

## 为什么适合：90 秒

> 第一，我做过实际使用的业务 Agent。经营托管场景让我理解必经步骤、证据不足、错误回答和失败降级这些问题，能从使用方角度看平台能力。
>
> 第二，我持续开发自己的 Coding Agent，接入过 OpenAI Chat Completions、Responses 和 Anthropic Messages 协议，实践上下文、权限、工具和协作机制。这让我对模型 API 和 Harness 有持续的工程兴趣。
>
> 第三，我有全栈交付和稳定性基础。腾讯实习里的 SDK 拆包、连接池和 native 内存问题，字节的性能采集和数据链路，能支撑我参与平台的接口、服务、控制台和观测研发。
>
> 我还需要补充分布式执行和云端多租户的深度，希望在团队里先承担具体模块，通过交付、评测和线上问题积累能力。

## SDK 封装不是简单转发：HR 层次怎么解释

> SDK 的价值是让开发者更容易正确使用服务。除了发请求，还要让参数、类型、流式事件、取消、错误和资源清理有清晰的使用方式。我的相关基础包括模型协议接入和监控 SDK 的模块设计；目标服务的具体 SDK 规范，需要结合团队接口和用户反馈继续学习。

追问清单：跨语言接口怎样一致；什么错误可重试；取消是否真正停止后台任务；资源由谁释放；包入口与示例是否可用。这里是设计题，不代表全部已经实现。

## 你对分布式 Harness 有什么差距

> 我已有 Agent Loop、上下文和工具执行的实践；分布式执行还要明确任务状态、worker 归属、故障恢复和副作用幂等。我不会把个人项目里的多 Agent 协作当作完整分布式生产经验。入职后希望沿着实际执行链路学习，并用故障注入和可观测数据验证理解。
