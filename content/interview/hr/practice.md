## 练习方法

先只看题目录音，回听后再看对应页面。一次回答先说结论，再给一个证据；第一次不要一次讲完所有技术。下列全部为模拟题。

## 15 分钟快练

| 时间       | 题目                           | 检查点                           |
| ---------- | ------------------------------ | -------------------------------- |
| 0–1 分钟   | 自我介绍                       | 开发身份、Agent 经历、岗位匹配   |
| 1–4 分钟   | 最有成就感的项目与追问         | 本人职责、结果口径、复盘         |
| 4–7 分钟   | 为什么团队、为什么 Managed API | 从业务 Agent 到平台的动机        |
| 7–9 分钟   | 最困难的事                     | 真实动作和验证，没有虚构救火情节 |
| 9–11 分钟  | 为什么深圳、职业规划           | 首选明确，技术与业务各有落点     |
| 11–13 分钟 | offer、薪资、到岗              | 真实数字、日期和条件             |
| 13–15 分钟 | 反问                           | 分工、成长、流程各一题           |

## 30 分钟完整模拟

1. 用一分钟介绍自己。
2. 在淘天具体做了哪些 Agent 全栈工作？
3. 其中什么是你独立负责，什么是团队成果？
4. 为什么要让 workflow 保证必要步骤？
5. 数字怎么测，误拦有哪些代价？
6. 从业务 Agent 转向平台研发，你缺什么？
7. 模型 API、SDK、Harness、云沙箱分别是什么？
8. 你通过实习熟悉云沙箱，具体负责过哪一层？
9. 腾讯 native 内存问题怎么定位和验证？
10. 讲一件真实做得不好的事，以及一次真实分歧。
11. 为什么从腾讯离开，这次又希望加入？
12. 为什么深圳，未来生活和工作怎么规划？
13. 技术和业务两方面的职业规划是什么？
14. 其他机会、薪资、论文和到岗有什么安排？
15. 你有什么想了解的？

## 连续追问 A：平台匹配

> 你适合我们吗？ → 哪一项是直接经验？ → 哪一项只是可迁移能力？ → 你在云沙箱里具体做过什么？ → 如果 worker 挂了怎么恢复？ → 你实际做过恢复机制吗？

合格标准：对已有经验讲出代码与验证；对设计题用「我会」；没有做过的分布式机制直接承认，不把 Agent Team 文件邮箱包装成生产调度系统。

## 连续追问 B：指标与商业化

> recall@5 为什么是 98%？ → 分母是什么？ → 幻觉率和它是不是同一批样本？ → 0% 误放是不是说明可以完全自动化？ → 降低了多少钱？

合格标准：不混指标和分母；承认样本局限；没有降本金额就说未掌握，转回已验证的上线能力与评测结果。不要把业务目标说成已经兑现的收入。

## 连续追问 C：深圳意愿

> 为什么深圳？ → 只是因为女朋友吗？ → 她以后离开深圳怎么办？ → 为什么不回南京或安徽？ → 其他城市薪资更高怎么选？

合格标准：首选深圳、长期发展、个人城市偏好和岗位方向相互一致；最后一题按真实权衡回答，不假装任何价差都不影响决定。

## 连续追问 D：职业规划

> 你的规划是什么？ → 技术怎么服务业务？ → 前沿技术和维护任务冲突怎么办？ → 你怎么理解 AI 提效？ → 怎么证明没有降低质量？

合格标准：既谈持续学习和全栈，也谈核心业务、验证、review 和用户反馈；不承诺入职即主导全公司战略。

## 回答评分

每项 0–2 分，总分 10 分。这是自评工具，不是腾讯评分表。

| 维度 | 2 分标准                                      |
| ---- | --------------------------------------------- |
| 事实 | 时间、职责、数字都有来源，不编造未知信息      |
| 匹配 | 能连接到 SDK、Harness、Managed API 或沙箱研发 |
| 表达 | 第一层回答简洁，追问时有细节                  |
| 责任 | 讲清本人动作、验证、失败和后续改进            |
| 意愿 | 深圳与职业方向清晰，承诺可兑现                |

出现虚构冲突、错误指标分母、假 offer 或捏造云平台成果，应先纠正事实，再练表达。

## 面试前事实卡

填写完成才能进入最后一轮模拟：

- 已确认：一年 gap 因新冠疫情相关身体原因；不补写未提供的当前健康结论。
- 已确认：字节和腾讯均因学校 WANProxy 校企科研安排离职；有一篇专利成果，已达到毕业要求。核对项目阶段日期、各次科研节点、专利状态和交接情况。
- 已确认：阿里广告已开出意向。补齐意向形式、截止日与交接周期。
- 已确认：希望加入腾讯云做前沿业务；HR 面继续推进且流程顺利后，主动结束其他意向和池子，不再考虑。
- 一次真实个人失败、一次真实分歧、一次具体协作。
- 云沙箱的场景、角色、动作、问题与验证。
- 模型 API 接入中最具体的一次故障或协议差异。
- 评测集、误放误拦、幻觉率与缓存的完整统计口径。
- 其他机会及截止日、薪资预期、最早到岗和出勤安排。

## 最后两分钟速记

> 身份：Agent 全栈研发。
>
> 自我画像：有理想、有激情、可靠；热爱学习、学习能力强，用 Agent 全栈实践支撑表达。
>
> 经历：淘天业务 Agent + 个人 Coding Agent + 腾讯 SDK/稳定性 + 字节性能。
>
> 匹配：分布式 Harness、Managed API、模型 API、SDK、云沙箱；熟悉和主导要区分。
>
> 意愿：深圳首选，女朋友在深圳，也有个人城市偏好，希望长期发展。腾讯云是长期愿景；已有阿里广告意向，腾讯云流程顺利后主动结束其他意向和池子。
>
> 时间线：gap 因新冠疫情相关身体原因；字节、腾讯因学校 WANProxy 科研安排离职；一篇专利成果，已达到毕业要求。
>
> 规划：技术服务业务，持续学习与端到端交付；理解核心业务、做好 AI 提效，与团队探索新场景和商业化。

## 连续追问 E：科研、gap 与选择意愿

> 一年的 gap 为什么？ → 字节和腾讯为什么都结束实习？ → WANProxy 做了什么？ → 专利是什么状态？ → 已达到毕业要求，什么时候能来？ → 阿里给意向了吗？ → 如果腾讯云继续推进，你怎么处理其他机会？

合格标准：用已确认事实直接作答；专利状态和到岗安排不虚构；阿里意向与正式 offer 区分；结束其他流程的意愿明确，同时保留本人提出的流程前提。
