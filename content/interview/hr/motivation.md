HR 面的「动机题」不是问你「喜不喜欢腾讯」，而是确认三件事：**你真的了解这个岗位吗？你会不会来？你来了会不会走？** 下面每题的答案都按「结论 → 理由 → 边界」组织；涉及未确认的事实用 `[待确认]` 标出，**不要用假话换 offer**。

## 为什么腾讯

**结论：** 腾讯是我优先级最高的选择，原因不是「大厂」，而是 **业务场景、工程标准、个人经历** 三件事同时匹配。

**1. 业务场景够真实、够复杂，而且从行业考虑我最想加入云业务。** 我在阿里妈妈做经营托管 Agent，服务的是商家经营；腾讯有社交、游戏、广告、云、内容等场景，Agent 不是做一个聊天入口，而是要嵌进真实业务链路。其中 **腾讯云（CSIG）的 ToB 场景是我从行业角度最看重的**：业务链路复杂、客户对稳定性/权限/评测的要求最高，最能检验「workflow + agent + 评测 + 权限」这套工程能力，而不是只调模型。

**2. 工程标准和我的一段经历对得上。** 我在腾讯 IEG 实习过，做 NoSQL 管理端的连接池、进程池、native 内存和前端监控。那段让我知道腾讯对稳定性、性能、可观测性的要求；这些正好是 Agent 上生产最容易缺的部分。

**3. 我在腾讯实习过，知道节奏和文化。** 我不是从招聘页上了解腾讯的；我待过 IEG 的团队，知道怎么和 DBA、native、前端同学协作。`[如果面试的不是 IEG，补一句：不同 BG 业务不同，但工程文化和协作方式是一致的。]`

**4. 岗位能把我三段经历串起来。** 字节让我会测量，腾讯让我会稳定，阿里让我会做 Agent；AI 全栈/Agent 岗位正好需要这三件事，而不是只要其中一段。

**5. Agent 开发正是腾讯当前明确缺人的方向。** 腾讯内部盘点的高需求方向是「混元（基座和应用）、微信（企微/视频号）、后训练和大模型应用、**Agent 开发**」。我不是挤进一个饱和赛道，而是踩在腾讯明确投入、明确缺人的方向上——这让「我为什么来」和「腾讯为什么要我」是同一个答案。

**边界：** 如果面试官问「你为什么不去阿里/字节」，不要贬低前两家；说「它们都很好，但腾讯的岗位和我的长期方向更匹配」。如果这不是你的真实首选，**不要照着说「第一优先级」**，改成「腾讯是我最看重的之一，我更看重岗位本身」。

### Q：为什么是腾讯，不是阿里/字节？

> 阿里和字节的实习让我学到很多，我不会贬低它们。选腾讯主要是三点：第一，从行业考虑我更看好云业务，Agent 嵌进腾讯云的 ToB 链路（以及社交/游戏/广告这些真实场景），比只做一个聊天入口有价值得多；第二，我在腾讯 IEG 实习过，知道团队对稳定性、性能、可观测性的要求，这些正好是 Agent 上生产最缺的；第三，这个岗位能把我「测量→稳定→自动化」三段经历串起来。薪资和 title 不是我的首要因素。

### Q：为什么是腾讯（用户为本 + 生态版，30 秒）

> 我认同腾讯「用户为本，科技向善」的产品思维。很多公司讲增长，腾讯更强调长期用户价值和产品沉淀——这一点我在 IEG 实习时能感觉到：做数据库管理端这种「用户是内部研发」的产品，团队一样会盯体验和稳定性。另外腾讯有成熟的 C 端生态和产业互联网布局，AI 的落地场景从社交、内容到云上的企业客户都有，不是只做一个聊天入口；这和我「把 Agent 从能聊做到能上线」的方向是同一件事。

**采分点：** 一句价值观 + 一个自己的观察 + 一个和岗位相关的落点。**雷区：** 只背「平台大、产品好用、福利好」；把「科技向善」讲成空口号，接不上自己的经历。文化细节与官方原文见 [腾讯文化与价值观](/interview/hr/tencent-culture-values)。

### Q：你眼里腾讯的核心优势是什么？

> 我会说三点：**生态、灰度、落地**。
>
> 生态是微信、QQ 这些产品带来的真实、完整的用户行为场景，AI 能力有地方被验证，而不是在实验室里自嗨。灰度是腾讯做产品的习惯——先在部分用户、部分流量上验证，再逐步放大，这对 AI 这种「输出不确定」的能力尤其重要。落地是团队不盲目跟风热点，更看重「用户是否真的需要、业务是否能闭环」；C 端体验和产业赋能两头都做，而不是只讲技术故事。
>
> 对我来说，这三点正好对应 Agent 上生产的三个难点：场景、可控、价值闭环。

**采分点：** 三个词各自展开一句，最后落到岗位。**雷区：** 「用户多、流量大、有钱」这类浅层答案；把「灰度」说成「保守、慢」；把「生态」只说成「流量入口」。

## 为什么腾讯云「技术与产品方向」

**结论：** 腾讯云（CSIG）的「技术与产品方向」是我把「Agent 工程化」落到 toB 平台的首选，因为它同时满足三件事：**场景够硬、工程要求够高、技术 + 产品能互相借力**。

**1. 这是把 AI 做成 toB/toG 平台的方向，不是做一个聊天入口。** 腾讯云这个方向做的是智能体开发平台（ADP）、企业级 OpenAPI、Agent Runtime 这类「被客户集成」的能力。企业买的不是一个聊天窗口，是能嵌进 CRM/工作台/小程序、可审计、可计费的能力——这正好要我这种「workflow + agent + 评测 + 权限」的工程能力。

**2. toB 是对工程能力要求最高的场景，正好是我的强项。** 客户对稳定性、权限、评测、审计的要求远高于 C 端；Agent 上生产最容易缺的就是这些。我在腾讯 IEG 做过连接池、native 内存、前端监控，知道这种工程标准；阿里经营托管 Agent 的置信度门控、500 题评估集，就是 toB 级的质量做法。

**3. 「技术与产品」是个组合，我两边都能讲。** 这个方向既招技术类（AI 全栈 / AI 应用 / 后台 / 前端）也招产品类（技术产品经理）。我的主线是技术（AI 全栈为主锚），但做过「定义误放/误拦指标」这种产品决策，也能聊技术产品经理岗——具体每个岗位的 JD 对照见 [岗位 JD 匹配](/interview/hr/jd-matching)。

**边界：** 不要把这个方向说成「什么都能投的兜底」。要讲清「我主投 AI 全栈工程师，技术产品经理是我能聊的第二选择，因为我有产品决策的经历」，方向清晰但不排斥。

### Q：技术岗和产品岗你怎么选？

> 我主投技术类的 AI 全栈工程师，因为我的主线是把 Agent 从「能聊」做到「能上线」，这是工程活。但我不排斥技术产品经理：我在阿里做经营托管 Agent 时，先定义的是「商家到底怕什么」，把「答错引发纠纷」变成误放率、误拦率两个可测指标，再反推架构——这就是产品决策。所以如果团队更需要懂技术原理的产品，我也能接；我的差异化正是「能判断什么能做、成本多少、风险在哪」。

## 为什么这个岗位与为什么 Agent 全栈

**结论：** 我想做的是 **能把 Agent 从「能聊」推到「能上线」的全栈工程师**，不是纯算法、纯前端或纯后端。

**理由：**

1. **Agent 的难点在链路，不在单点。** 模型能力是上游，真正的工程问题在：工具怎么调度、权限怎么隔离、上下文怎么压缩、失败怎么恢复、效果怎么评测、成本怎么控制。只做一端，很难对最终结果负责。
2. **我有端到端交付的经历。** 阿里经营托管 Agent：workflow 编排 + RAG + 置信度门控 + A2UI + 前端模块联邦；腾讯：Node/native + 连接池 + 监控 SDK + React 迁移；字节：采集 + 数据链路 + 虚拟滚动。前端、服务端、数据、native 都碰过。
3. **我不是「什么都会一点」。** 我的主线是 Agent 工程化；前端/后端/native 是为了把这条主线落地。面试时我会明确说「我最擅长 Agent 工程化和服务端，前端能独立交付，但不会把自己包装成纯前端专家」。

**如果岗位偏前端：** 「我可以做前端，我的 React/TS、监控 SDK、虚拟滚动、模块联邦都是实战；但长期我希望往 Agent 全栈走，前端是我交付链路的一部分。」

**如果岗位偏后端：** 「后端/服务端是我的强项之一，Node/Go、连接池、native、监控都做过；Agent 方向我也能接。」

**雷区：** 「我都可以」「公司安排什么我做什么」——HR 会认为你没有方向；但也不要说得太窄，让岗位无法匹配。

## 为什么离开阿里与为什么看机会

**事实口径（已确认）：** 阿里实习已结束；转正还不明确（今年 HC 很紧缺）；从行业考虑更希望加入腾讯云业务。

**标准答法（不贬低、不抱怨）：**

> 我在阿里妈妈做经营托管 Agent，这段让我确认了 Agent 在真实业务里的价值，也让我知道自己想长期做这个方向；实习结束时项目已经在淘宝商家端落地。现在看机会，主要是因为 **从行业考虑，我更希望加入腾讯云业务**：ToB 场景业务链路复杂、对 Agent 的稳定性/权限/评测要求最高，最能发挥我这套工程能力；腾讯的岗位和我的主线也最匹配。阿里这段我收获很大，也很感谢团队给的机会；我是带着感谢离开的，不会说前东家不好。

**如果问「阿里给你转正了吗？」**

> 「转正目前还不明确，今年 HC 很紧缺。我不想把时间耗在不确定的等待上；而且即使有转正机会，从行业考虑我也更希望加入腾讯云业务，所以秋招我认真推进腾讯。」

- **不要虚构**「阿里给了 SSP/高薪转正」来抬价；HR 交叉询问、背调、offer 对比很容易穿帮。
- 说「HC 紧缺」是客观陈述，语气要中性，不要带「阿里不行了」的情绪。

**如果问「那你为什么不留在阿里？」**

> 两个原因：客观上，实习已经结束，转正还不明确（今年 HC 紧缺）；主观上，我的判断是——**下一段我更想要「云/ToB 的业务复杂度 + Agent 工程化深度」，而不是换一个同样做广告 Agent 的地方。** 腾讯有社交/游戏/广告/云这些场景，尤其腾讯云的 ToB 业务对 Agent 工程化要求最高，我也有在 IEG 见过的工程标准，所以我优先看腾讯。

**如果问「你实习换了三家，是不是待不住？」** 见 [频繁实习与稳定性](/interview/hr/narrative#频繁实习与稳定性) 与本文最后一节「稳定性」。

## 城市与稳定性

:::warning base 城市陷阱（最高频翻车点，务必先读）
真实面试里多位候选人翻车在同一个点（见 [base 城市陷阱样本](/interview/hr/real-questions#形态-gbase-城市陷阱样本腾讯广告)）：**想当然认为「腾讯 = 深圳」，大谈深圳好、贬北京上海，结果岗位 base 上海/成都，当场减分**。你要面的腾讯云「技术与产品方向」岗位 base 各不相同：**AI 全栈工程师**有深圳/北京/上海/广州/成都/杭州，**技术产品经理**有深圳/北京/上海/成都/杭州，**AI 应用工程师**有深圳/北京/上海/广州/成都（注意「Agent 开发工程师」不含这个方向，见 [岗位 JD 匹配](/interview/hr/jd-matching)）。所以：

1. **面试前务必确认目标部门/岗位的实际 base**（可从 JD、HR、或反问环节确认）；
2. **不要贬低任何城市**——你贬低的那个城市，可能正是岗位 base；
3. 城市回答用「**以岗位和团队为先 + 给一个真实可接受的范围**」，不要踩一捧一。
   :::

**结论：** 首选深圳；北京/上海可以接受；不会说「哪里都行」。

> 我的首选是深圳。原因有三个：第一，腾讯总部在深圳，Agent/AI 相关的业务和团队密度高；第二，我在南京读书，也在外地实习过，适应独立生活；第三，我老家在安徽芜湖，深圳的交通回家方便，父母这边我会沟通好，他们更看重我的长期发展 `[按真实情况]`。
>
> 如果岗位在北京或上海，我也可以接受，但我会先确认团队和业务是不是我长期想做的；我不会为了拿 offer 说「全国都可以」，因为入职后发现城市不合适，对双方都不负责。

**追问「父母在安徽，为什么去深圳？」**

> 我本科就在西安，研究生在南京，已经独立生活多年；父母更看重我的长期发展，不是必须我在身边。深圳到芜湖交通方便，我也会定期回去。`[如果父母其实不希望你去，别说「支持」；改成「我和家里沟通过，他们尊重我的选择，我也会平衡」]`

**追问「会不会想家/稳定性」**

> 我实习一直在外地，独立性没有问题。城市选择我看的是长期职业发展，不是短期离家近；如果团队和方向匹配，我会稳定待下去。

**追问「女朋友/对象在哪个城市？」** 见下一节；不要为了「稳定」编造。

**雷区：** 「都可以」「听公司安排」「我女朋友在深圳所以我去深圳」——前者显得没主见，后者会让 HR 担心你是为感情而不是为工作来，且一旦感情变化就离职。

## 其他 offer 与优先级

**结论：** 诚实说「有/没有」，但把重点放在「为什么腾讯优先」，不要报具体数字，不要贬低其他公司。

**如果有其他 offer/流程：**

> 目前有在其他流程中的机会 `[按真实情况]`，但还没有签三方。腾讯是我的第一优先级，原因是我更看重 Agent 全栈的长期方向和云/ToB 的业务复杂度，而不是单纯比较薪资。如果腾讯给我 offer，我会认真、快速地做决定，不会拖着。

**如果没有其他 offer：**

> 目前主要在推进腾讯，也有其他公司在早期流程，但还没有 offer。我很清楚自己想做 Agent/全栈，所以不会为了「有个保底」随便签一家；腾讯是我最想去的。

**如果问「其他公司给你更高薪，你会去吗？」**

> 薪资是重要因素，但不是唯一因素。我会看岗位方向、团队、成长空间和总包结构；如果腾讯的岗位更匹配，我不会只因为差一点薪资就走。`[如果腾讯薪资明显低，不要硬说「不在乎钱」；说「会在总包和成长之间做综合判断」]`

**如果问「给你 offer 你会来吗？」**

> 如果岗位和地点匹配，我会来。我可以明确说，腾讯是我当前优先级最高的选择；我也理解您关心接受率，我不会拿腾讯的 offer 去抬价，也不会在签约前临时反悔。`[只有这是真话时才说]`

**雷区：** 「我手里有阿里/字节的 offer，你们给多少？」——HR 面不是谈薪面，容易引起反感；「我都可以，看谁给的钱多」——接受率直接归零。

## 家庭与亲属

HR 问这些不是八卦，是判断 **稳定性、异地意愿、是否有隐性约束**。回答原则：**简短、真实、正向、不展开隐私**。

### Q：有没有对象？

> 目前 `[单身 / 有稳定伴侣]`。感情状况不会影响我的工作选择，家里这边我会沟通好 `[按真实情况]`。`[如果有伴侣异地，补一句：我们沟通过，她/他支持我先发展，长期会一起规划。]`

**雷区：** 编一个「女朋友在深圳」来证明稳定；或者说「有对象但异地，可能以后要回去」——后者会让 HR 直接担心你离职。

### Q：是不是独生子？

> `[是 / 不是]`。父母身体都还好 `[按真实情况]`，也支持我先在外面发展；家里没有需要我立刻回去的负担。`[不要编「父母身体不好」或「家里有产业要继承」]`

### Q：有没有直系亲属在腾讯？

> 没有 `[按真实；如有，如实说明不会影响工作安排；隐瞒没有意义，背调/入职信息可能查到]`。

### Q：父母是做什么的/家庭情况？

> 普通家庭，父母在安徽 `[按真实情况]`。他们更看重我的长期发展，支持我先在深圳/外地工作 `[按真实情况]`。`[不需要详细职业/收入；HR 通常只是判断家庭是否支持异地。]`

### Q：身体状况怎么样？

> 身体健康，没有影响工作的疾病，可以正常体检。`[不要主动说「能加班」；如果确有需要说明的情况，如实但不展开。]`

### Q：有没有结婚/生育计划？

> 目前没有近期计划，我更关注职业发展。`[如果被追问，礼貌地说「这属于个人规划，目前没有确定时间表」；不要编。]`

## 岗位方向不一致

**场景：** 你投的是 AI 全栈，HR 问「如果入职后做游戏服务器开发，和你的成长方向不一样，能接受吗？」

**答法（诚实版）：**

> 我可以接受短期做业务需要的方向，因为底层能力是相通的：长连接、状态同步、性能、稳定性、故障定位，这些我在腾讯 IEG 和字节都练过。但我不想为了拿 offer 说假话：我长期想做 Agent/AI 全栈，如果团队明确需要我长期做纯游戏后端、和 Agent 完全没交集，我可能需要再考虑。如果这个岗位里有一部分 AI/Agent 相关的工作，或者 1–2 年内能转过去，我很愿意先把它做好。

**答法（如果岗位就是 AI 全栈）：** 「这正是我想做的方向，不需要纠结。」

**采分点：** 诚实 + 可迁移能力 + 边界。**雷区：** 「我完全接受」但入职三个月就转岗/离职；「我只做 Agent，其他不做」——太窄，直接出局。

## 业务理解题

### Q：游戏服务器后端与普通互联网后端的区别？

> 我没做过游戏服务器，所以先说我的理解，再说可迁移的部分：
>
> | 维度   | 游戏服务器                                        | 普通互联网后端                   |
> | ------ | ------------------------------------------------- | -------------------------------- |
> | 连接   | 长连接为主（TCP/WebSocket），连接数大、生命周期长 | HTTP/RPC 为主，无状态、短连接    |
> | 状态   | 有状态：房间/场景/玩家状态，内存态多              | 尽量无状态，状态外置到 Redis/DB  |
> | 一致性 | 帧同步/状态同步，顺序和实时性要求高               | 最终一致、幂等、补偿             |
> | 延迟   | 毫秒级、抖动敏感                                  | 吞吐和尾延迟，通常百毫秒级可接受 |
> | 运维   | 分区/合服/热更新/回滚                             | 滚动发布/灰度/弹性扩缩容         |
> | 安全   | 防作弊、协议加密、外挂对抗                        | 鉴权、限流、风控                 |
>
> 相通的是：连接池、内存/GC、监控、压测、故障定位、容量规划。我在腾讯 IEG 做过 TCP 连接池、native 内存和监控，这些能直接迁移；帧同步/状态同步/分区这些我需要补，但我学得很快。

**采分点：** 先承认没做过，再给结构化对比，最后给可迁移能力。**雷区：** 不懂装懂，把「帧同步」和「状态同步」说反；说「游戏后端就是高并发」——太浅。

### Q：你对游戏开发的看法？

:::danger 真实被挂案例
IEG 魔方后台的 HR 面问「对游戏开发的看法」，候选人答「接触的不多」，HR 明显不满意，随后进池子（后被捞回、最终 OC）。**HR 面永远不要说「不了解 / 接触不多」**——这是态度题，不是知识题。
:::

> 我从三个层面说。第一，个人接触：我玩过 `[按真实情况填一两款具体游戏/类型]`，对 `[玩法/社区/商业化]` 有自己的观察。第二，技术理解：游戏后端和普通互联网后端不一样——长连接、有状态、实时性要求高，状态同步和反作弊的工程复杂度很高（上一题展开过）。第三，和经历的结合：我在腾讯 IEG 实习时做的 TcaplusDB 管理端，服务的就是游戏业务，我知道游戏对稳定性和延迟的苛刻要求。所以我的看法是：游戏开发是技术要求高、用户反馈即时的领域，我的稳定性工程和 Agent 工程能力在这里都能直接用。

**如果确实不玩游戏（诚实版）：**

> 说实话我不是重度玩家，但我认真研究过游戏业务的技术特点：长连接、状态同步、实时性要求高。而且我在腾讯 IEG 实习时服务的就是游戏业务，理解稳定性和延迟对游戏意味着什么。兴趣可以培养，工程能力是直接可迁移的。

**采分点：** 有具体细节（玩过的游戏/研究过的点）+ 和经历挂钩（IEG 实习服务游戏业务是你的独有优势）。**雷区：** 「接触的不多」（真实被挂案例的原话，送命）；假装重度玩家被 HR 深聊拆穿。

### Q：Agent 在广告业务上怎么实现自动化和提效？

> 我在阿里妈妈做的就是经营托管 Agent，所以这题我可以结合真实经历说。广告业务的 Agent 提效可以分四层：
>
> 1. **经营托管/客服**：商家问「为什么没曝光/怎么调价/预算怎么分」，Agent 查订单、查政策、查投放数据，给出建议；高风险的执行动作（改预算/改出价）需要人工确认。这正是我在阿里做的场景。
> 2. **投放诊断**：把「曝光下降/转化变差」拆成可查的指标树，Agent 按 workflow 拉数据、定位原因、给优化建议；不是让模型自由发挥，而是每一步都有工具和证据。
> 3. **创意/素材生成**：根据商品、人群、历史素材生成文案/图片/视频脚本；生成后要过合规/品牌安全检查，不能直接投放。
> 4. **客服与培训**：把重复问题、政策解释、投放教学做成 RAG + Agent，降低客服/讲师人力成本；用采纳率、解决率、误承诺率评估。
>
> 架构上我会用 **workflow + agent**：查订单/查政策/拉报表这些必经步骤走 workflow，证据足够后的判断和表达交给 agent；生成前做置信度门控，不够就追问/转人工；再用数据飞轮持续迭代。
>
> 指标上不只看「回答了多少」，要看 **人力成本下降、首响/解决时长、建议采纳率、误承诺率、投放效果（ROI/转化）**。广告业务错误承诺的代价很高，所以我会把「可审计、可回滚、human-in-the-loop」放在第一位。

**采分点：** 有真实项目、有架构、有指标、有风险。**雷区：** 把 Agent 说成「接个 LLM API 就能自动投放」；忽略合规和错误成本。

### Q：如果面的是广告/商业化产品岗，四个核心是什么？

:::note 适用范围
这不是腾讯云（CSIG）岗位的主答案；如果 HR 面来自广告/商业化团队（如 AMS、视频号商业化），或者面试官从「Agent 在广告业务提效」继续往商业逻辑追，用下面四条接。**没有广告业务实操的部分要明说是公开信息 + 自己的判断，不装内部数据。**
:::

1. **增长拆解 + 数据迭代闭环**：先把「增长」拆成曝光、点击、转化、客单价这些可归因的指标，再定义每一步的 baseline、实验口径和迭代周期；不是讲「用 AI 提升效率」，而是讲「哪一段漏、怎么验证、多久复盘一次」。
2. **广告商业化的底层逻辑**：广告本质是「用流量换预算」，平台要同时服务广告主 ROI、用户体验和平台收入；三方冲突时，短期靠出价/竞价机制平衡，长期靠供给质量和生态健康。Agent 能提效的环节是诊断、创意、客服和投放操作，但**改预算/改出价这类动作必须有边界和人工确认**。
3. **视频号当下的变现理解**：视频号是腾讯广告里「内容 + 社交 + 商业化」交汇的场景，变现离不开广告加载、直播电商和商家经营；我的判断是它的价值不只在流量增量，更在把社交关系链和交易链路接起来。**具体产品动作和数字以官方公开信息为准，我不编内部口径。**
4. **AI 落地可控、有边界、懂兜底**：广告业务错误承诺和误操作的成本很高，所以我会把 workflow 的必经步骤、置信度门控、人工确认、审计回滚放在模型能力之前；指标上不只看采纳率，也看误承诺率、投诉率和投放效果。

**采分点：** 每条都能落到「指标 / 机制 / 风险」中的至少两个。**雷区：** 把广告说成「流量生意，价高者得」；用「AI 自动投放」跳过合规和人工兜底；对视频号讲没有出处的内部数字。

**补充：即使没有实操，也能讲清的产品理解**（2026-11 核实，完整版见 [云业务与 Agent](/interview/qa/cloud-business-agent) Q19）：

> 我不会说「精通」，但官方产品页和文档我认真看过，能讲清它的分层和取舍：智能体开发平台 ADP 按业务复杂度给了四种范式（Claw / 标准 / 工作流 / Multi-Agent），Agent 与 Workflow 双向互调；企业级 OpenAPI 开放了 10 大模块、100+ 接口，让 Agent 长进客户自己的 CRM、工作台、小程序；下面 Agent Runtime 提供沙箱、记忆、网关和可观测，TokenHub 供模型。**我理解这套设计的关键是「构建—分发—治理」加「被集成」**——企业买的不是一个聊天窗口，是能嵌进流程、可审计、可计费的能力。

### Q：你觉得 Agent 赛道是泡沫吗？

> 短期有泡沫，长期是基础设施。模型能力会继续变强，但 Agent 的胜负手不只是模型，而是 **场景、数据、工程约束、成本**。我看好「workflow + agent + 评测 + 权限」这条工程化路线：纯 prompt 的 demo 很容易被复制，真正难的是让它在业务里稳定、可审计、可回滚。我在阿里做的就是这件事，所以我不是追风口，而是把它当长期方向。

### Q：你为什么不读博/为什么做工程？

> 我更喜欢工程落地和快速验证。读论文、看源码我也做，但我不想把职业路径放在科研上；我希望做出来的东西有人用、有反馈、能迭代。实习和开源项目让我确认了这一点。

### Q：你更偏前端还是后端？

> 偏 **服务端/Agent 工程**，但前端能独立交付。我做过 React/TS、监控 SDK、虚拟滚动、模块联邦，也做过 Node/Go 服务、连接池、native 和监控。我的优势是端到端，而不是只写一端；如果岗位需要，我可以偏一端，但不会把自己限制死。

## 稳定性

**如果问「你会不会干两年就走？」**

> 不会。我三段实习是在验证方向，不是习惯性跳槽；现在方向明确是 Agent 全栈，我希望在腾讯长期做深。频繁换公司对技术积累没有好处，我也清楚这一点。`[如果你确实有读博/回老家/创业计划，不要撒谎；可以说「目前没有，未来如果有我会提前和团队沟通」]`

**如果问「你怎么保证来了不会觉得无聊？」**

> 我看的是业务复杂度，不是新鲜感。Agent 在腾讯的场景里还有很多没解决的问题：效果、成本、权限、评测、多 agent 协作；这些够我做很多年。新鲜感会过去，但问题不会。

**如果问「你为什么不自己创业/做独立开发？」**

> 我喜欢做产品，但现阶段我更想在真实业务里练工程能力。`yukino-code` 是我业余的作品，但它不能替代大规模业务的复杂度；我想先在腾讯把 Agent 的工程化做深，再谈别的。

:::note 动机题的底线
**真话不全说，假话全不说。** 城市、offer、家庭、转正状态这些信息，HR 会交叉确认；一个假话需要十个假话去圆。你可以选择「不展开」，但不要编造。HR 面最加分的不是「完美答案」，而是「这个人可信、想来、待得住」。
:::
