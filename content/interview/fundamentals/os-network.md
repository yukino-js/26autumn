本章把系统层题目串成两条主线：**单机资源与调度**（进程、内存、IO）和**跨机通信**（TCP/IP、实时媒体）。答题时先给边界定义，再给成本与失败模式。

## 一、进程、线程与协程

| 概念 | 资源边界                                       | 调度方 |
| ---- | ---------------------------------------------- | ------ |
| 进程 | 资源分配最小单位，独立地址空间、fd 表、页表    | 内核   |
| 线程 | CPU 调度最小单位，共享进程内存，各有栈与寄存器 | 内核   |
| 协程 | 用户态轻量执行单元，程序自己调度，不陷内核     | 运行时 |

**并发是逻辑同时**（单核时间片轮转，同一时刻只跑一个），**并行是物理同时**（需多核）。协程适合 IO 密集与高并发连接；CPU 密集、需要抢占式公平调度或依赖阻塞式系统调用的场景不适合。

## 二、内存布局与分配器

```text
高地址
  ┌──────────────┐
  │ 栈 stack      │  局部变量 / 调用帧 / 返回地址, 向下增长
  ├──────────────┤
  │ 空闲区        │
  ├──────────────┤
  │ 堆 heap       │  malloc/free, 向上增长
  ├──────────────┤
  │ .bss          │  未初始化全局/静态, 默认 0
  ├──────────────┤
  │ .data         │  已初始化且非 0 的全局/静态
  ├──────────────┤
  │ .rodata       │  字符串字面量, 只读
  ├──────────────┤
  │ .text         │  机器指令, 只读
  └──────────────┘
低地址
```

`malloc` 底层用 `brk()` 推堆顶（小内存）或 `mmap()` 映射匿名页（大内存）；空闲块由空闲链表 / 伙伴系统维护，块头 `struct malloc_chunk` 记录大小与空闲标志，`free(p)` 靠 `p − 偏移` 找到头部。**`free` 后 glibc 通常把块放回空闲链表供复用，而不立刻归还 OS**——所以 RSS 不降不等于泄漏。实现差异：glibc ptmalloc、tcmalloc、jemalloc 在多线程 arena 与碎片治理上取舍不同。

## 三、IPC 与 IO 多路复用

| 方式            | 特点                                  | 代价                       |
| --------------- | ------------------------------------- | -------------------------- |
| 匿名管道 / FIFO | 字节流无格式；FIFO 可无亲缘           | 单向、容量有限             |
| 消息队列        | 有格式、支持优先级                    | 内核大小限制、拷贝         |
| **共享内存**    | 最快，用户态直接访问，免内核/用户拷贝 | 同步、管理、大小固定、安全 |
| 信号量          | 只做同步，不传数据                    | —                          |
| Socket          | 可跨机                                | 开销大                     |
| 信号            | 异步通知                              | 信息量极少                 |

共享内存四大缺点：**并发写需额外同步**、申请释放需所有进程协调、大小固定扩容要重建、能访问的进程都能读写。

| 模型       | 复杂度               | 关键点                                                  |
| ---------- | -------------------- | ------------------------------------------------------- |
| `select`   | 每次全量遍历 fd 集合 | fd 上限 1024、每次重传集合                              |
| `poll`     | 仍全量遍历           | 链表无 1024 限制                                        |
| `epoll`    | 只返回就绪 fd        | 红黑树管 fd + 就绪双向链表                              |
| `io_uring` | 提交/完成双环        | SQPOLL 免系统调用、固定文件与固定缓冲省去重复注册与拷贝 |

**LT vs ET**：LT 只要仍有未读数据就持续通知；ET 只在状态变化时通知，因此**必须循环读到 `EAGAIN`**，否则剩余数据再也不会被唤醒。`read` / `mmap` / Direct I/O 的取舍：普通小 IO 用 `read`，随机读大文件用 `mmap` 省一次拷贝但要处理缺页与地址空间，自管缓存的数据库用 Direct I/O 绕过 page cache。

## 四、网络分层与 TCP

| OSI 七层           | TCP/IP 四层 |
| ------------------ | ----------- |
| 应用 / 表示 / 会话 | 应用        |
| 传输               | 传输        |
| 网络               | 网际        |
| 数据链路 / 物理    | 网络接口    |

TCP 面向连接、可靠、有序、有流量与拥塞控制；UDP 无连接、无序、轻量。**三次握手不能是两次**：既防历史重复连接初始化，也要同步双方初始序列号。四次挥手的 `TIME_WAIT` 保证最后一个 ACK 可达并让旧连接的迟到报文消散。

:::warning TCP 是字节流协议
没有消息边界。应用层解析器必须自己定义长度前缀或分隔符，并设置**单条消息上限、状态机、超时与非法输入拒绝**，否则畸形输入能让解析器无限等待或内存膨胀。Protobuf 靠字段编号兼容增删字段，但改字段类型、复用已删除编号会破坏兼容；gRPC 的 deadline、cancel、retry 会互相影响——客户端取消后服务端可能仍在执行，重试必须配幂等键。
:::

## 五、C++ 与系统底层易错点

| 陷阱                                      | 后果 / 正解                                                 |
| ----------------------------------------- | ----------------------------------------------------------- |
| 严格别名与 `reinterpret_cast`             | 编译器按类型假设优化，跨类型访问是 UB                       |
| `memmove` 与重叠区间                      | `memcpy` 重叠是 UB，重叠必须用 `memmove`                    |
| `string_view` 悬空                        | 不持有所有权，底层 string 销毁或扩容后失效                  |
| `vector` 扩容                             | 元素被复制或移动，之前的引用/迭代器失效                     |
| `compare_exchange_weak` 伪失败            | 必须在循环里重试，不能当一次判定                            |
| 无符号整数溢出                            | 回绕导致循环条件永真                                        |
| DCL 双重检查锁                            | 缺内存屏障时发布未构造完成的对象                            |
| 信号处理函数里调 `printf` / `malloc` / 锁 | 非异步信号安全，可能死锁；只设 `volatile sig_atomic_t` 标志 |
| 缺页异常                                  | 内核查 VMA → 分配页框或换入 → 更新页表 → 重新执行触发指令   |

## 六、WebRTC 与万人房间

| 组件     | 职责                                                                                      |
| -------- | ----------------------------------------------------------------------------------------- |
| **SDP**  | 描述媒体能力（编解码、方向、指纹、ICE 参数），**不负责传输**                              |
| **ICE**  | 收集 host / STUN 反射 / TURN 中继候选，做连通性检查并提名                                 |
| **STUN** | 只发现 NAT 映射，不保证直连                                                               |
| **TURN** | 对称 NAT / 严格防火墙下中继；凭证须**服务端签发带过期时间的临时凭证**，不能硬编码在客户端 |

流程：信令交换 Offer/Answer → 持续交换 Candidate → DTLS 握手 → 音视频走 SRTP、数据通道走 SCTP over DTLS。

**弱网 QoS**：先按 RTT、丢包率、队列延迟判断是不是拥塞，再决定 NACK 重传 / RTX 重传包 / FEC 冗余。低 RTT 且数据仍有播放价值用重传；高丢包或来不及重传用 FEC，但额外耗带宽。**不能见丢包就加 FEC 或疯狂重传**；音频连续性优先，降视频保音频。

**SFU 不混流**，按订阅关系转发媒体包，瓶颈不只是连接数，还有出口带宽、包复制、加密、拥塞控制状态与订阅频繁变更。单机接收所有流再扇出会先打满网卡；房间状态集中在单节点时加机器无效。解法：按发布流 / 订阅用户**分片 + 级联 SFU**（上游流跨区只传一次、区域本地扇出）、限制同时可见视频轨、**Simulcast / SVC** 选层，**控制面**（成员、分配、故障迁移）与**媒体面**（只留转发状态）分离。

## 七、面试怎么讲

| 加分                                            | 扣分                       |
| ----------------------------------------------- | -------------------------- |
| 先给资源/调度边界，再谈成本与数量级             | 只背「进程是资源分配单位」 |
| 主动讲 LT/ET 的 `EAGAIN`、字节流无边界          | 把 TCP 当消息协议          |
| 云厂商/万人房间题先找瓶颈（带宽、包复制、状态） | 「加机器就行」             |
| 弱网先判拥塞再决定冗余策略                      | 见丢包就加重传             |

## 速记卡

- **进程管资源、线程管调度、协程在用户态**；并发 ≠ 并行。
- **`free` 不必然归还 OS**；RSS 不降不等于泄漏，要看三次 GC 后的 retained size。
- **epoll** = 红黑树管 fd + 就绪链表；**ET 必须读到 `EAGAIN`**。
- **三次握手**防历史连接 + 同步双方序列号；**TIME_WAIT** 保最后 ACK 与旧报文消散。
- **SDP 描述、ICE 选路、STUN 找映射、TURN 兜底**；SFU 靠分片级联而非堆机器。
