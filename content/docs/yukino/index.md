yukino-code 仓库 `apps/yukino` (Yukino Code, npm 包 `@yukino.js/yukino`, Node >= 20) 的系统性源码笔记, 共 29 个页面 (含本落地页). CLI 用 React 19 + Ink 7 渲染单窗格终端界面, 通过可配置的 LLM Provider 驱动「模型到工具再回到模型」的自治循环; 全部文档以该仓库源码为唯一事实依据. 总览篇见 [what-is-an-agent](./what-is-an-agent) 与 [yukino-code](./yukino-code), 其余页面按子系统拆分, 顺序与侧边栏一致.

| 页面                                           | 内容概要                                                                                                                                                                                                                                                                 |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| [a2a](./a2a)                                   | A2A (Agent2Agent) 互通协议: `--a2a` 模式下 Yukino 作为 A2A 服务器运行 (默认监听 127.0.0.1:18890), 基于 `@a2a-js/sdk` 以标准化服务暴露能力, 供其他 agent 或编排器发现、派发任务并消费流式状态更新                                                                         |
| [acp](./acp)                                   | ACP (Agent Client Protocol) 编辑器集成: `--acp` (stdio) 与 `--acp-ws` (WebSocket, 默认 127.0.0.1:18889) 模式下 Yukino 把自身实现为 ACP agent, 供 Zed 等兼容编辑器以 JSON-RPC 驱动初始化、会话、提示词与权限确认                                                          |
| [agent-team](./agent-team)                     | Agent Team 网状多代理协作: 每个 teammate 是有独立上下文窗口的 agent 实例, 相互之间可发送邮件; 协调建立在共享任务板 (tasks.json) 与成员邮箱 (inboxes/) 之上, 邮件以文件加轮询投递, 突破 subagent 星型拓扑不能互通的限制                                                   |
| [agents-md-and-memory](./agents-md-and-memory) | AGENTS.md 与三层记忆: 工作记忆 (上下文窗口本身)、持久化到磁盘的长期记忆 (用户/项目级指令文件 AGENTS.md、JSONL 会话日志加文件快照, 支撑恢复会话与检查点回退), 以及 Agent 在对话中自动积累经验的自动记忆                                                                   |
| [code-review](./code-review)                   | Code Review: 收敛为一条 `/review` slash command 加一个内置 `review` subagent 角色, 审查 agent 用 gh CLI 拉取 PR 详情与 diff、用常规只读工具读代码与项目指令, 发现以文字直接返回当前会话供主 agent 继续动作                                                               |

| [function-calling](./function-calling)         | 工具调用 (function calling): LLM 负责决策、CLI 负责执行 — 覆盖协议本身、Tool 接口与 ToolRegistry、内置工具的实现要点、各宿主的装配差异, 以及流式解析和执行管线                                                                                                           |
| [goal](./goal)                                 | 持久目标 (Persistent Goal): GoalManager 状态机、/goal 命令与 Goal 工具三件套, 让 agent 跨轮次、跨用户消息朝一个目标自动推进 — 循环退出前先问是否续跑, 直到完成、受阻或预算耗尽                                                                                           |
| [hook](./hook)                                 | Hook: 在生命周期事件上挂载自动化动作 (事件/条件/动作三要素) — 写文件后自动 format、危险命令执行前拦截、会话开始时注入项目约定; 配置只来自 `~/.yukino/config.yaml` 顶层 hooks 数组                                                                                        |
| [llm](./llm)                                   | LLM 层 (src/llm/): 把对话历史翻译成三种协议的 LLM API 请求, 将各家返回的 SSE 流统一映射成内部 StreamEvent 事件流供 Agent Loop 消费, 并负责思考强度、token 计费口径、prompt cache 打点、错误分类重试与模型发现                                                            |
| [lsp](./lsp)                                   | LSP 集成: 内置只读 stdio JSON-RPC 客户端 (src/lsp/client.ts) 与 LSP 工具 (src/tools/lsp.ts), 把定义、引用、类型定义、实现、调用链、诊断等 11 种语义级查询暴露给 agent, server 配置来自 `~/.yukino/config.yaml` 的 lsp_servers                                            |

| [permission](./permission)                     | 权限系统: 对每次工具调用给出 allow/ask/deny 判定, 以显式规则、模式矩阵、安全命令白名单、路径沙箱、OS 沙箱、hook 多层短路, 抵御 prompt 注入、越权与数据泄露三类攻击面                                                                                                     |
| [print-mode](./print-mode)                     | Print 模式: `-p` 非交互执行, 面向脚本、CI 与 Unix 工具组合场景; runPrintMode() 自行组装完整运行时, 消费 agent.run() 事件流按输出格式打印到 stdout, 结束时清理所有子进程与后台任务                                                                                        |
| [react-and-agent-loop](./react-and-agent-loop) | ReAct 与 Agent Loop: 推理与行动交替的范式如何落成代码 — Agent.run() 事件循环的每一轮做什么、何时退出、出错如何自愈, 以及工具如何分批执行                                                                                                                                 |
| [remote](./remote)                             | Remote 模式: Express HTTP 服务器加同端口 WebSocket 桥 (默认监听 127.0.0.1:18888), 浏览器打开 React 前端得到与终端 UI 功能对齐的聊天界面 — 流式回复、工具执行卡片、权限对话框、plan 审批、slash 命令、模型/provider 切换                                                  |
| [sandbox](./sandbox)                           | OS 级沙箱: 把 Bash 命令放进操作系统提供的隔离环境执行, 文件系统写入收敛到允许的目录内、网络可整体关闭; 沙箱开启后破坏半径被 OS 收敛, 权限层可免人工确认 (auto_allow)                                                                                                     |
